# FairShare

Рабочий MVP для студенческих команд, спроектированный по `M1_product_vision_filled.pdf`. Язык интерфейса — русский. Задачи, аккаунты, сессии, обсуждения и голосования сохраняются в PostgreSQL.

Развёрнут на VPS: **https://fairshare.15.235.192.28.sslip.io**. Деморежим на сервере отключён; создайте свой аккаунт. Команды управления, обновления и резервного копирования: [инструкция VPS](deploy/README.md).

## Запуск

Нужен Node.js 22.12+; проверено на Node.js 24.19.0.

```bash
npm ci
npm run build
npm start
```

Откройте **http://localhost:3000** и нажмите **«Открыть демо»**. Или зарегистрируйте свою команду. Встроенная PostgreSQL PGlite автоматически создаст `.data/postgres`; Docker, API-ключи и облачный аккаунт для локального запуска не нужны. Сохранённые данные переживают перезапуск. Один каталог PGlite должен использоваться только одним серверным процессом.

Для разработки:

```bash
npm run dev
```

Интерфейс: http://localhost:5173, API: http://localhost:3000. Не запускайте `start` и `dev` одновременно на одной базе и порту.

## Что работает

- Регистрация, вход, выход и серверные HttpOnly-сессии.
- Команды и одноразовые приглашения на 24 часа; участник может состоять в нескольких командах.
- Несколько проектов и недельных этапов, общая доступность участника по неделям.
- Задачи с целью, первым шагом, ожидаемым результатом, оценкой часов и обязательным навыком.
- Предложение распределения, объяснение каждого назначения, подтверждение координатором после обсуждения с командой.
- Учёт незавершённой нагрузки во всех проектах на одну неделю; сохранение исполнителей задач в работе.
- Доска, личные задачи, ручное назначение с явным подтверждением исключения, зависимости с защитой от циклов.
- Запрос помощи в один клик; для завершения — ссылка или описание результата.
- Обсуждения внутри задач, чек-листы, общие ссылки, предложения решений, голосование и фиксация итога.
- Журнал действий и адаптивный интерфейс. Изменения команды обновляются опросом раз в 15 секунд и при возвращении в окно.

## Проверки

```bash
npm run typecheck
npm test
npm run build
```

Тесты создают отдельную PostgreSQL в памяти и не меняют вашу локальную базу. Они проверяют распределение, основной сценарий API, права команд, одноразовые приглашения, конфликты, обсуждения, чек-листы и голосования.

Также проверены сохранение данных после повторного открытия PostgreSQL, сохранение зависимостей при частичном изменении задачи и пересчёт при изменении нагрузки в другом проекте. 10 автоматических тестов прошли.

Браузерные сценарии:

```bash
npm run test:e2e
```

Используется системный Chromium, если он установлен; иначе браузер Playwright. Если браузера нет, установите его `npx playwright install chromium`. Можно задать `CHROMIUM_PATH`. Тесты поднимают отдельную базу в памяти и локальный сервер, проверяют основной desktop-сценарий, подключение второго участника/голосование и мобильный экран. 3 октября 2026 года все 3 браузерных сценария прошли. На VPS также проверены регистрация по HTTPS, безопасная сессия, создание задачи, сохранение данных после перезапусков и откатов, а также восстановление резервной копии в отдельную PostgreSQL-базу.

## Обычная PostgreSQL

При наличии `DATABASE_URL` сервер автоматически использует адаптер `pg`. Строку подключения задавайте секретом окружения. Настройте TLS так, как требует выбранный провайдер; проверку сертификата отключать не следует. SQL-схема использует стандартные ограничения PostgreSQL; база не должна содержать чужие таблицы с совпадающими именами.

Для внешнего размещения задайте `NODE_ENV=production`, `ENABLE_DEMO=false` и `APP_ORIGIN` с точным HTTPS-адресом приложения. Сервер должен находиться за HTTPS-прокси. В этом режиме сессия использует Secure-cookie, а демовход по умолчанию отключён. Локальный `.env` автоматически не читается: передайте значения через менеджер окружения или команду `node --env-file=.env --import tsx server/index.ts`.

## Границы версии

Это MVP, развёрнутый на VPS с отдельной PostgreSQL и HTTPS. Вход не проверяет владение email; восстановления пароля пока нет. Нет отправки писем, загрузки файлов, push-уведомлений и WebSocket-синхронизации. Голосование — средство обсуждения; итог решения фиксирует координатор вручную. Этап длится одну выбранную неделю; оценки — в шагах 0,25 часа. Алгоритм эвристический и не обещает глобально оптимальное распределение или устранение пассивности.

Демонстрационные аккаунты существуют только при включённом деморежиме. Для проверки роли участника в локальном демо: `suusar@fairshare.demo` или `sezim@fairshare.demo`, пароль `FairShare-demo-2026!`. Эти данные учебные; перед внешним размещением используйте отдельную чистую PostgreSQL и отключите деморежим.
